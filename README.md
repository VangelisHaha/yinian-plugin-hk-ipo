# 港股新股（yinian-hk-ipo）

安时（Nuncta）的日历同步插件：把港股新股的四个时点变成日历上的事件。

数据来自华盛证券的公开页面，**不需要账号、Token 或任何凭据**。

## 它做什么

一只新股会生成最多四个事件：

| 事件 | 形态 | 例 |
|---|---|---|
| 认购截止 | 定时 | `认购截止 02261 拿森科技` |
| 公布结果 | 全天 | `公布结果 02261 拿森科技` |
| 暗盘 | 定时，默认 16:15–18:30 | `暗盘 16:15-18:30 02261 拿森科技` |
| 上市 | 全天 | `港新上市 02261 拿森科技` |

为什么是四个事件而不是一条跨天的：它们是**四件要分别做的事**——今天下午几点前
要下单、后天晚上暗盘能挂、周一开盘。压成一条跨天块，日历上只剩一根横条，
反而看不出哪天该干什么。

不想全都要的话，在实例设置里只勾你关心的时点（只看上市日就只留「上市」）。

## 事件都是「空闲」

这些是信息提示，不是占用你时间的会议。全部标成 `free`，不会把接下来一周的
忙闲视图涂满。

## 关于暗盘时间

暗盘（Grey Market）是**券商在上市前一晚撮合的场外交易**，不是港交所盘内交易，
时间固定在上市日前一个港股交易日的 16:15–18:30。

数据源的「暗盤時間」列大多数时候是 `--`（券商开放前不填），所以：

1. 页面给了日期 → 用页面的，来源字段标「来自页面」
2. 页面没给 → 按**上市日前一个非周末日**推导，标题带「（推导）」

> **推导值请以券商公告为准。** 插件不内置港股公众假期表——那需要农历库来算农历
> 节日，与这个插件零运行时依赖的前提冲突。碰上长假前后的新股，在实例设置的
> 「额外的港股休市日」里补一下日期即可。

## 日历是只读的

同步来的事件落在一个只读日历里，在安时这侧改不了。这是 event 同步的产品语义：
外部日历里的事情是外部已经发生的事实，两边各改一半再合并，结果和两边都不一致。

不想看了就在日历侧栏把这个来源隐藏，不需要删事件。

## 上市之后

上市完成的票会从数据源页面上消失，插件**不会**因此把历史事件标成「已取消」——
那是「已经发生」，不是「被撤回」。

真的撤回（招股失败、延期）会被识别出来：插件记住每只票的上市日，
如果一只票从页面消失而上市日还在未来，才按撤回上报。

## 设置

### 插件级

| 字段 | 默认 | 说明 |
|---|---|---|
| 抓取超时 | 20 秒 | 5–60 秒 |
| User-Agent | 内置浏览器 UA | 一般不用改 |

### 每个实例

| 字段 | 默认 | 说明 |
|---|---|---|
| 日历名称 | 港股新股 | 显示在日历侧栏 |
| 同步哪些时点 | 全选 | 认购截止 / 公布结果 / 暗盘 / 上市 |
| 覆盖哪些阶段 | 全选 | 可认购 / 待上市（「已递表」没有确定日期，不采） |
| 暗盘时段 | `16:15-18:30` | 数据源给了具体时段时以它为准 |
| 额外的港股休市日 | 空 | 逗号分隔的 `YYYY-MM-DD`，推导暗盘日期时跳过 |
| 数据源地址 | 华盛证券公开页 | 一般不用改 |

「测试数据源」按钮会真抓一次并列出前几只票，启用前就能看到会同步进来什么。

建议同步间隔 **1 小时**（下限 30 分钟）。新股信息一天只变几次，抓太勤没有意义。

## 开发

```bash
npm ci
npm run verify        # build + doctor + 测试
npm run pack:zip      # 打可安装的 zip 到 release/
```

只依赖 TypeScript 与 `@types/node`，运行时零依赖。抓取用 Node 20 内置的
`fetch`，不 spawn `curl`——那样安装时的权限清单会多一条「执行外部命令」，
而用户没法判断那意味着什么。

### 代码结构

| 位置 | 职责 |
|---|---|
| `src/ipo/parse.mts` | HTML 解析：按 `<h3>` 分段 + 按 `<thead>` 定位列 |
| `src/ipo/events.mts` | IPO 行 → 日历事件，含暗盘推导 |
| `src/ipo/fetch.mts` | HTTP 抓取 |
| `src/handlers/sync.mts` | `sync.pull` 与撤回记账 |
| `src/handlers/config.mts` | 配置校验与「测试数据源」 |

### 解析器有个不能退回去的坑

页面按 `<h3>` 分成可認購 / 待上市 / 已遞表三段，前两段表结构相同**但第 8 列
语义不同**（可認購是認購截止時間，待上市是暗盤時間）。而且「可認購」为空时页面
渲染成 `<!---->`，连 `tbody` 都没有。

用「`可認購` 之后第一个 `tbody`」的正则会串到「待上市」表，把暗盘时间当成认购
截止写库。所以必须**按段取表 + 按表头文字定位列**，两条都不能省。
`tests/parse.test.mjs` 里有这条回归。

## 契约

按安时的插件契约实现，`PROTOCOL_VERSION = 1`，需要宿主 **0.6.0 以上**
（event 同步是 0.6.0 才有的能力）。契约见安时仓库的
`docs/11-plugin-architecture.md` §5.1.1。
